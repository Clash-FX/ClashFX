# 首次启动修复的第二轮独立复核 — 2026-10-21（未发布）

在 1.1.11.14 后续修复上继续检查首次启动重试、恢复基线、远程切换和诊断脱敏。本轮修复不改变自动恢复节点选择和 DNS 配置规则。历史首次失败的核心原始错误已经被旧版丢弃，仍不能据人工端口冲突负例断言其根因。

## 发现与修复

- **恢复配置的身份必须重新确认。** 内置核心 resume 会先启动 config.yaml；没有冻结订阅图时，清除旧的已确认订阅标记，保持启动基线身份。冻结图无法解码、应用拒绝或读回不一致时隔离失败核心。仅在冻结图应用并读回验证后恢复订阅标记；空 external-controller 仍允许合法的纯原生控制配置。
- **连续重启失败不能丢失恢复基线。** 重启前冻结正在运行的内置配置，Helper 启动失败后恢复该图。再次重启尚无新事务 receipt 时，只复用与已验证订阅身份匹配的冻结图，不把任意 lastSubmitted 配置认作订阅。增强模式切换已经暂停内置核心时，不覆盖先前冻结图。
- **配置事务忙碌时不启动重启。** 更新中、待处理更新或事务仍在验证时返回非模态提示，保留冻结图和订阅身份，避免清空基线后继续停止核心。
- **Remote → Local 应真正激活当前订阅。** 远程冷启动后切回 Local，经旧核心清理和 ownership 门禁启动本地订阅；运行中的本地已确认订阅与当前所选订阅不同时走普通配置事务。相同订阅不重复加载，活动增强模式不重复启动。清理尚未确认时等待安全重试；外部 ownership 不确定时不启动或停止核心。
- **成功回滚不应抹掉真实失败原因。** 订阅 B 拒绝、回滚到 A 时，仅由经过当前作用域确认的成功回滚同步更新外层期望订阅名，避免把自己的基线恢复误认为用户切换作用域。真正的订阅、远程、API、核心或 generation 变化仍取消旧回调；回滚原因保留脱敏后的核心错误。
- **凭据值不能靠右括号或第一个引号猜边界。** 脱敏扫描支持 YAML 双单引号、转义双引号、嵌套集合、流式注释和多行值；凭据中的 `]`、`}`、注释括号不会提前终止脱敏。结构畸形、深度或输入超限时封闭处理。先识别凭据结构再改写 URL，避免 URL 替换文本干扰集合边界。保留端口占用等安全诊断，不改变配置接受规则。
