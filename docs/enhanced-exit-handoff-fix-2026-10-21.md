# 增强模式退出失败与内置核心重试保护（2026-10-21）

## 现场事实和结论边界

本机仍运行 Lab 1.1.11.14。只读日志显示：18:26:51 退出增强模式并启动自定义 mixed 端口 7088；18:26:53 完整配置重载被拒绝，之后出现 MATCH/DIRECT 请求超时；18:27:11 再次退出时 7088 端口检查失败；18:27:37 新外置核心的 API/TUN/DNS 验证通过。当前 GET /version、/configs、/proxies 可响应，代理条目为 171 个。

旧版本日志只记录了通用的 Core rejected the runtime configuration，不能据此还原第一次拒绝的底层错误。事后未找到 7088 的可见监听，也不能用事后结果确定故障当时的占用者。已确认的代码缺口是重载失败仍恢复 callbacks，使启动初始配置可能继续承载流量，以及重试未完整执行订阅恢复。

## 修复

在现有候选源码上继续修改，保留 macOS 10.14 目标：

- 确认外置核心停止后，暂停回调并 suspend 自身内置核心，释放前次失败可能留下的监听和缓存，再通过 startProxy 保留自定义端口、API、LAN 和 IPv6 启动设置；不单独提前 reopen 缓存。
- startProxy 返回脱敏后的实际启动/检查点恢复错误，不再用通用的重启失败覆盖原始原因，也不在失败后记录启动完成。
- 新 completeBuiltInProfileHandoff 供首次退出和失败重试共用。完整订阅验证成功，或失败后完整订阅基线仍得到验证，才恢复回调；仅初始配置、状态未知或未验证时 suspend 核心并保留显式重试入口。
- 早期配置拒绝只允许通过已验证 receipt 恢复基线元数据；不单凭旧 profile 名字提升快照的验证状态。
- 绑定生命周期、core session、交互 generation、远端身份和 API context，过期完成不得停掉或恢复新运行实例。
- 失败时增强模式偏好反映实际持有的核心状态；停核重试显示 mixed。启动时已偏好增强模式，或启用 Claude 锁时，停核重试仍允许直接恢复增强模式。
- 事务已验证并发布完整配置后即完成退出；后续可选元数据刷新不再持有退出令牌，避免其 API 重试耗尽不回调导致界面永久处于切换中。
- 新增 Built-in Handoff 分阶段日志，记录启动失败、完整订阅恢复、完整订阅保留和停核保护；错误内容沿用统一脱敏。
- 独立复查指出停核后重试可能覆盖冻结检查点并经增强模式失败回退到初始配置。已在 captureBuiltInRecoveryCheckpoint 中拒绝从停核或增强模式状态重新捕获；checkedResumeBuiltInCore 的所有发布调用均要求已验证的完整 profile，否则停核并返回错误。
