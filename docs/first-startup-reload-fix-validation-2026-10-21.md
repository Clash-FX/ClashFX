# 首次启动重载修复与隔离验证 — 2026-10-21（未发布）

已在 1.1.11.14 源码基础上修复可证实的启动处理和日志问题。历史那次核心拒绝的具体错误已被旧版丢弃，无法还原；人工端口占用负例不等于历史故障根因。

## 已证实的问题与修复

- 原先 Swift 将嵌入核心的所有非 success 返回替换为通用拒绝提示。现保留脱敏后的原始返回；nil、空返回、超时和作用域变化保持不确定结果，不伪报确定成功或确定拒绝。HTTP 确定拒绝也保留 JSON 错误信息。
- 原先重载期间 callbacksPaused 会丢掉 Go 的 bind 等底层错误。现只允许 error 级日志在暂停期间送达线程安全日志回调，普通日志和流量回调仍暂停。回调中的错误经过脱敏，日志包含阶段、请求 UUID 和 epoch；UI 仅显示必要的错误原因。
- 启动错误弹窗原先在配置完成回调之前运行，阻断随后增强模式恢复。现由启动流程处理错误，先推进恢复；增强模式最终验证成功后记录恢复结果，避免中间失败阻断目标模式启动。普通手动重载的错误展示保持原有行为，静默策略也随排队请求传递。
- 仅在启动初始基线下，候选配置被确定拒绝且旧基线重新应用、验证成功后，再校验并重试一次。验证失败、不确定结果、回滚失败、取消或旧回调均不会触发盲目重试。普通已确认订阅切换的默认重试策略不变。
- 回滚明确区分“启动初始配置”与“已验证订阅配置”。未确认订阅时，启动基线不能触发系统代理自动恢复；初始加载与增强恢复均失败时暂停初始核心，保留增强模式意愿和明确失败状态。外部核心 ownership 不确定时不误停核心或恢复 DNS。
- 新独立复核发现远程控制提前返回会遗留启动恢复等待状态。已补齐入口和回调的远程取消路径，清理 timer/in-flight，并保留用户的代理恢复意愿；切回同端口的已确认本地配置也能重新恢复。

日志对 URL 中的身份、路径和查询参数，以及认证列表、密码、token、UUID、私钥等字段脱敏并限制长度。非法脱敏表达式会 fail closed，不输出原始内容。未修改其他 DNS 引用或节点选择策略。

完整编译使用本机 SDK 27，仅在私有副本通过命令行覆盖为 macOS 12；主项目、Pods 和 Podfile 仍为 10.14。此验证不代表实际运行过 macOS 10.14，也没有执行本机真实 TUN、系统 DNS/代理切换或授权弹窗。
